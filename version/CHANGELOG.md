# 更新日志

TempMail Manager 各发布版本说明。GitHub Releases 的 tag 与本文件的小节一一对应，
每个版本的可执行文件放在本目录（`version/`），命名规则：

```
TempMailManager-v<版本>-win64.exe
```

> 本目录下的 exe 不进仓库（`.gitignore` 忽略），只在 GitHub Release 页面手动上传；
> 本文件（`CHANGELOG.md`）进仓库，作为发版文案的唯一来源。
> 发版步骤：① 改 `build.py` 里的 `APP_VERSION` → ② `python build.py` 打包 →
> ③ 把 `build/TempMailManager.exe` 复制为本目录的 `TempMailManager-v<版本>-win64.exe` →
> ④ 确认本文件已是最新 → ⑤ 建 tag 并上传 exe。
> 若本次改了数据库结构：还要 `migrations.py` 里加 `_migrate_to_vN` + `LATEST_VERSION` + `STRUCT_CHECKS`，
> 并把新列同步进 `database.py` 的 `SCHEMA`（全新库建表即最新），升级说明里写清备份与回滚方式。

## v1.1.1 — 2026-11-11（待发布）

发布文件：待打包 `TempMailManager-v1.1.1-win64.exe`

修复版：单个邮箱续期不再丢掉所选时长。

### 修复

- **单点续期忽略所选时长**：点某个邮箱的「续期」并选好时长后，请求里没有带时长，
  后端一律按 30 天续；连默认的「保持当前有效期」也会把 7 天 / 10 分钟的邮箱改成 30 天。
  现在按所选时长续期，不选则沿用该邮箱当前有效期
- **非法时长**：传入不在白名单里的时长现在直接返回 `400`，不请求站点、不改库
  （此前后端不校验，照样调站点并按 30 天落库）
- **续期范围**：单点续期只影响被点的那个邮箱，不会波及其它邮箱（已用离线桩验证：
  站点只收到一次针对该 uuid 的续期请求，其它邮箱的有效期与续期时间均不变）

### 文档

- `docs/接口文档.md`：`POST /api/mailboxes/:id/renew` 补齐可选请求体 `{"lifetime": "7d"}`、
  缺省行为与 `400` 的说明

### 升级说明

- 直接替换 exe 即可，数据库结构无变化，数据不受影响

## v1.1.0 — 2026-11-08

发布文件：`TempMailManager-v1.1.0-win64.exe`

功能更新：备注更隐蔽、隐私更安心。

### 新增

- **备注默认隐藏**：邮箱卡片上的备注最多显示一行且不展开内容，只显示「📝 备注（点击查看）」，
  点击展开 / 再点收起；完整内容随时可点「改备注」弹窗查看与修改
- **隐私显示**：顶栏新增「隐私显示」开关，开启后邮箱地址只显示前 5 位和后 5 位
  （中间打码），卡片、顶部详情、备注弹窗同步生效；开关状态会被记住，
  按钮高亮但不改变大小，不影响旁边按钮位置


### 升级说明

- 直接替换 exe 即可，数据库结构无变化，数据不受影响

## v1.0.1 — 2026-11-08

发布文件：`TempMailManager-v1.0.1-win64.exe`

改进版：续期更智能（可选时长、启动不抢跑），修复剩余天数显示。

### 新增

- **立即续期可选时长**：点「续期」弹窗选择要续到多久，默认「保持当前有效期」
  （7 天邮箱续期后还是 7 天，不再被强行续到 30 天）；设置里「自动续期时长」
  也新增了「保持各邮箱当前有效期」选项

### 修复

- **剩余天数按有效期计算**：此前"剩余约 N 天"固定按 30 天倒计时，新建 7 天 / 15 天的邮箱
  也显示"剩余约 30 天"；现在按邮箱自身的有效期倒计时（7d 显示 7，15d 显示 15），
  分钟 / 小时档（10 分钟 ~ 6 小时）改为显示"剩余约 N 小时 / 分钟"
- **启动时不再立即续期**：此前自动续期开启时，程序启动 5 秒后就会把所有开启自动续期的
  邮箱续一遍；现在首次启动只记录基线时间，等满设定的间隔（默认 24 小时）才开始自动续期

### 升级说明

- 直接替换 exe 即可，数据库结构无变化，数据不受影响

## v1.0.0 — 2026-11-08

发布文件：`TempMailManager-v1.0.0-win64.exe`

首个公开版本，Windows x64 单文件 exe，数据全部保存在本地 SQLite。

### 功能

- **邮箱管理**：一键创建 onetimeemail.com 临时邮箱，可选有效期（10 分钟 / 30 分钟 / 1 小时 /
  3 小时 / 6 小时 / 24 小时 / 3 天 / 7 天 / 15 天 / 30 天，默认 30 天并记住上次选择），
  支持备注、手动续期、自动续期开关
- **未读提醒**：邮箱卡片显示未读数量，点开邮件即自动标记已读并实时更新角标
- **多级分组**：无限层级分组树，未分组视图，分组重命名与删除
- **拖动排序与嵌套**：分组行按高度分三段判定——拖到中间「放入该分组」，拖到上下边缘「同级排序」，
  拖到「未分组」即回到顶层；带环路检测（不会把父分组拖进自己的子分组），顺序持久化到数据库
- **邮箱拖进分组**：把邮箱卡片拖到左侧任意分组上即移入，拖到「未分组」即移出；
  拖已勾选的卡片会整批移动
- **批量管理**：邮箱区右上角「管理」进入勾选模式，多选后统一「移入分组」，分组下拉带层级缩进，
  支持全选 / 退出
- **自动续期**：内置调度器每日巡检，为开启自动续期的邮箱续 30 天
- **批量导入**：粘贴文本 / 文本文件 / Excel（xlsx）三种方式批量导入已有账户
- **批量导出**：一键导出全部邮箱（含 uuid / 助记词 / cookies）为 Excel
- **收信查看**：邮件列表与详情，HTML 邮件在沙箱 iframe 中渲染，支持放大查看，点击外链安全跳转
- **日志中心**：业务 / 系统 / 前端请求 / 外部 HTTP 四通道日志入库，可搜索、脱敏展示
- **数据库结构版本化**：`schema_version` 表 + 迁移注册表，启动时自动检查并升级老库；
  升级前自动整库备份为 `data/tempmail.db.bak-v<旧版本>`，备份成功才改结构；
  控制台、「运行日志」与页面顶部提示条都会告知升级明细；全新安装不产生备份；
  用旧版程序打开新库不会被降级

### 界面改进

- 分组展开标记：18px 圆角按钮（浅底 + 描边），展开时旋转 90°，子分组一目了然
- 设置里的「续期时长」与新建邮箱共用完整的 10 档中文有效期选项

### 打包说明

- 单文件 exe（Nuitka），`--onefile-tempdir-spec` 固定解包目录，避免 %TEMP% 残留
- 运行后数据保存在 exe 同级 `data/` 目录；SmartScreen 拦截时点「更多信息 → 仍要运行」（未做代码签名）
- 仅提供 Windows x64；Linux / macOS 请按 README 用源码运行
