# onetimeemail.com 站点协议（逆向记录）

> 2026-11-06 通过抓取 `https://onetimeemail.com/assets/app.js` + curl 实测确认。
> 站点改版时先重新看这份，再改 `app/services/client.py`。

## 基础

- 站点根：`https://onetimeemail.com`
- 语言前缀：`/zh-hans`（也支持 `/en`、`/ja` 等）。前缀只影响返回文案，接口路径都挂在语言前缀下。
- 鉴权模型：**uuid 即凭证**。创建时站点下发 `uuid` 和 12 词 `recovery_phrase`，任何人拿到 uuid 就能读写该邮箱。

## 1. 取 Cookie 与 CSRF

```
GET /zh-hans/
```

响应头下发：

```
Set-Cookie: PHPSESSID=<32位>; HttpOnly
Set-Cookie: preferred_language=zh-hans
```

页面内含：

```html
<meta name="csrf-token" content="927c3503...">
```

表单也有 `<input name="csrf_token" value="...">`，两处取其一即可（代码优先 meta，回退 input）。

## 2. 创建邮箱

```
POST /zh-hans/create_inbox.php
Cookie: PHPSESSID=...
X-CSRF-Token: <上面那个 token>
X-Requested-With: XMLHttpRequest
Accept: application/json
Origin: https://onetimeemail.com
Referer: https://onetimeemail.com/zh-hans/
```

无 body。响应：

```json
{"success":true,
 "email":"gary.harris5913@odessalux.com",
 "uuid":"fdc4978e-c047-43f6-9c61-f7ee7cd0674f",
 "recovery_phrase":"over bulk slice alert dove uncle sketch weekend orphan online balcony fly",
 "lifetime":"1h"}
```

- **默认有效期 1h**，必须再调第 3 步改成 30d。
- CSRF 过期返回 **403**，官方前端会重新 GET 表单取新 token 再试一次，本例同样重试一次。

## 3. 设置/续期有效期

```
POST /zh-hans/api/api_update_lifetime.php
Content-Type: multipart/form-data 或 application/x-www-form-urlencoded
uuid=<uuid>&lifetime=30d
```

响应：`{"success":true}`

- 合法值只有：`10m, 30m, 3h, 6h, 24h, 3d, 7d, 15d, 30d`
- 非法值返回 `{"success":false,"error":"Invalid lifetime option."}`
- **这个调用就是续期**：把空闲计时重置为所选时长。每天调一次 30d 即可长期保留。
- 实测**不需要 Cookie**，只要 uuid。

## 4. 读信

```
GET /zh-hans/api/api_check_emails.php?uuid=<uuid>
```

响应（空箱）：

```json
{"success":true,"email":"...","recovery_phrase":"...","lifetime":"30d","emails":[]}
```

有信时 `emails` 数组元素字段（前端渲染代码确认）：

| 字段 | 含义 |
| --- | --- |
| `id` | 邮件 id（本地用作 remote_id） |
| `sender` | 发件人显示名/地址 |
| `subject` | 主题 |
| `received_at` | 站点给的格式化时间字符串 |
| `body_html` | HTML 正文，可能为空 |
| `body_text` | 纯文本正文，HTML 为空时兜底 |

- uuid 失效（过期/被删）返回 `success:false`，前端会提示收件箱不可用。
- 同样**不需要 Cookie**。
- 注意：该接口一次返回全部邮件正文，没有分页，也没有附件字段。

## 5. 删除邮箱

```
POST /zh-hans/api/api_delete_inbox.php
uuid=<uuid>
```

响应 `{"success":true}`。删除不可恢复。

## 6. 异常行为（实测）

| 场景 | 站点返回 |
| --- | --- |
| 邮箱已删除 / 过期后调 `api_check_emails.php` | **HTTP 403 + 一整个 HTML 错误页**，不是 JSON |
| CSRF token 过期时创建 | HTTP 403 + JSON `{"success":false}` |
| `lifetime` 传非法值 | `{"success":false,"error":"Invalid lifetime option."}` |

所以 `client._json()` 必须容忍非 JSON 响应，`check_emails()` 对非 200 直接给出中文提示，避免把 HTML 片段抛给用户。

删除接口实测 **不需要 Cookie 和 CSRF**，只要 `uuid` 表单字段，返回 `{"success":true}`；重复删除同一 uuid 仍是 200 success。

## 复现命令

```bash
curl -c cj.txt -A "Mozilla/5.0" https://onetimeemail.com/zh-hans/ -o page.html
CSRF=$(grep -oE 'csrf-token" content="[a-f0-9]+' page.html | grep -oE '[a-f0-9]{40,}')
curl -b cj.txt -c cj.txt -H "X-CSRF-Token: $CSRF" -H "X-Requested-With: XMLHttpRequest" \
     -X POST https://onetimeemail.com/zh-hans/create_inbox.php
curl -F "uuid=<uuid>" -F "lifetime=30d" https://onetimeemail.com/zh-hans/api/api_update_lifetime.php
curl "https://onetimeemail.com/zh-hans/api/api_check_emails.php?uuid=<uuid>"
```

## 变更风险点

站点一旦改动，以下三处最先失效，改动集中在 `client.py`：

1. CSRF 的 meta 名或位置变了 → `fetch_csrf()` 的正则
2. 创建接口路径/字段名变了 → `create_inbox()`
3. `emails` 数组字段改名 → `normalize_emails()`（已做 sender/from、body_text/body 兼容）
