# 本项目 HTTP 接口文档

Base：`http://127.0.0.1:8720`
所有接口返回 `{"success": bool, "data": ..., "error": "..."}`。
失败时 HTTP 状态码同时非 200/201。

## 页面

### GET /
返回单页应用 HTML。

### GET /api/health
```json
{"success": true, "data": {
  "lifetimes": ["10m","30m","3h","6h","24h","3d","7d","15d","30d"],
  "default_lifetime": "30d",
  "renew_interval_seconds": 86400
}}
```

### GET /api/logs
日志中心，按 `kind` 取不同通道：

| kind | 内容 | 字段 |
| --- | --- | --- |
| `business`（默认） | 业务动作 | level/action/mailbox_id/message/created_at |
| `system` | 启动、中断标记、500 摘要 | 同上 |
| `access` | 前端请求 | method/path/query/status/duration_ms/ip/request_body/error/created_at |
| `http` | 对站点的外部请求 | method/url/status/duration_ms/request_body/response_body/error/job_id/mailbox_id/created_at |

- `level`：business/system 可用（info/warn/error）
- `keyword`：access 按 path/error，http 按 url/响应内容，business/system 按 message
- `only_error=1`（http）：只看 4xx/5xx 或网络错误
- `status_min`（access）：按状态码过滤
- `raw=1`（http）：返回未脱敏原文（uuid 完整、助记词明文），诊断用
- 默认（不带 raw）输出全部脱敏：uuid 只留前 8 位，recovery_phrase 与 PHPSESSID 显示为 ***

### DELETE /api/logs?kind=
按通道清空：`business` / `access` / `http`（system 与 business 同表，清 business 会一起清掉）。

### DELETE /api/logs
清空全部日志，返回 `{"removed": n}`。清空动作本身会留一条 `clear` 日志。
日志总量超过 2000 条会自动裁剪最旧的（每写 50 条检查一次）。

### DELETE /api/db-notice
关闭页面顶部「数据库结构已升级」提示条，删除 `settings_kv` 里的 `db_upgrade_notice`。
只影响提示，不动数据；返回 `{"dismissed": true}`。提示由 `pages.index` 注入模板，没升级时不渲染。

## 分组

### GET /api/groups
平铺返回所有分组（前端自己组树），每项额外带 `mailbox_count`（**仅直属**数量，子树统计在前端做）。
```json
[{"id":1,"name":"项目A","parent_id":null,"created_at":"...","mailbox_count":2}]
```

### POST /api/groups
```json
{"name": "项目A", "parent_id": null}
```
`parent_id` 为空即顶级分组。名称必填、≤50 字，同级允许重名。成功返回 `201`。

### PATCH /api/groups/:id
```json
{"name": "新名字"}                  // 改名
{"parent_id": 3}                    // 移动
{"parent_id": null}                 // 移到顶层
```
只会更新传入的字段。防环校验：不能把分组挂到自己或自己的子孙下面，否则 `400`。

### DELETE /api/groups/:id
级联删除该分组及**全部子分组**，组内邮箱的 `group_id` 置空（回「未分组」），邮箱本身保留。
```json
{"success": true, "data": {"removed_groups": 2, "ids": [3, 4]}}
```

## 邮箱

### GET /api/mailboxes
列表，每项在 `mailboxes` 表字段外附带 `email_count`、`unread_count`。

### POST /api/mailboxes
创建邮箱。请求体：
```json
{"auto_renew": true, "note": "", "group_id": null, "lifetime": "30d"}
```
- `auto_renew` 是否每日自动续期，默认 true
- `group_id` 直接建到某个分组，可空；分组不存在返回 `404`
- `lifetime` 有效期，取值见 `GET /api/health` 的 `lifetimes`（10m/30m/1h/3h/6h/24h/3d/7d/15d/30d），默认 `30d`；
  不在白名单内返回 `400`
- `type` 固定为 1（服务端写死，不接受外部指定）

成功 `201`：
```json
{"success": true, "data": {
  "id": 1, "email": "xxx@mycloudmail.net", "uuid": "...",
  "recovery_phrase": "over bulk slice ...", "lifetime": "30d",
  "auto_renew": true, "type": 1, "group_id": null,
  "created_at": "2026-11-06 11:12:40",
  "last_checked_at": "...", "last_renewed_at": "...", "last_error": ""
}}
```
站点异常时返回 `502` 与 `error` 文案（如「创建临时邮箱失败。」）。

### GET /api/mailboxes/:id
单个邮箱详情。

### POST /api/mailboxes/move
批量把邮箱移入一个分组（左侧拖拽或「批量管理」调用）。
```json
{"ids": [1, 2, 3], "group_id": 4}
```
- `group_id` 传 `null` 表示移到「未分组」，分组不存在返回 `404`
- 成功：`{"success": true, "data": {"moved": 3, "group_id": 4}}`，并写一条 `move` 业务日志

### PATCH /api/mailboxes/:id
```json
{"auto_renew": false}      // 或 {"note": "注册 ChatGPT 用"}
```
- `note`：备注，服务端先 `strip()` 再截断到 200 字；传空字符串即清除备注。
- `group_id`：移动到分组；传 `null` / `0` / `""` 表示移出分组；分组不存在返回 `404`。
- 三个字段可同时传。
返回更新后的邮箱；不存在时 `404`。

### DELETE /api/mailboxes/:id?remote=1
删除邮箱。`remote=1`（默认）会先调站点删除接口，失败也删本地（记 warn 日志）。
`remote=0` 只删本地。

### GET /api/mailboxes/import/template
下载 Excel 导入模板（`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`）。

- 内容：表头 `UUID | 助记词` + 3 个示例账户，列宽已设好
- 文件名：`邮箱导入模板.xlsx`（同时带 ASCII 兜底名 `mailbox-import-template.xlsx`）
- 模板由 `services/xlsx_writer.py` 用标准库现生成，不落盘
- 示例 uuid 是**假值**，照抄导入只会得到 3 条「收件箱不可用」，不会误入库

### POST /api/mailboxes/import
批量导入账户。两种调用方式，返回结构相同。

**方式一：JSON（粘贴文本 / 文本文件内容）**
```json
{"text": "uuid,助记词\n0650a8f9-..., over bulk slice ...", "group_id": null, "auto_renew": true}
```

**方式二：multipart 文件**
| 字段 | 说明 |
| --- | --- |
| `file` | txt / csv / tsv / md / log（按 UTF-8→GBK 顺序尝试解码）或 xlsx / xlsm |
| `group_id` | 可选，导入到哪个分组 |
| `auto_renew` | `1` / `0`，默认 1 |

解析规则：每行只要含合法 uuid 即可识别，助记词可选、顺序随意；表头行（含 uuid / 助记词 / phrase / mnemonic 等词）自动跳过；`#` 开头为注释。Excel 会把每行单元格拼成字符串后走同一套规则，因此列顺序无关。

返回：
```json
{"success": true, "data": {
  "total": 4, "parsed": 3,
  "imported":  [{"id": 5, "email": "a@b.com", "uuid": "...", "line": 2, "new_mail": 1}],
  "duplicated":[{"line": 3, "uuid": "...", "email": "c@d.com", "reason": "该 uuid 已在列表中"}],
  "invalid":   [{"line": 4, "text": "这是一行无效内容"}],
  "failed":    [{"line": 5, "uuid": "...", "error": "收件箱不可用或已过期..."}]
}}
```
- 单次上限 300 行，超出部分忽略
- 重复判定同时看 uuid 和 email，批内重复也会提示「与本文件第 N 行重复」
- 站点不可达/邮箱失效会落到 `failed`，不影响其他行

### POST /api/mailboxes/:id/renew
立即续期**单个**邮箱，同时刷新 `last_renewed_at`。只操作路径里的这一个邮箱，不影响其它邮箱。
请求体可选：
```json
{"lifetime": "7d"}
```
- `lifetime` 取值见 `GET /api/health` 的 `lifetimes`；不传或传 `null` 时沿用该邮箱当前的有效期
  （前端「保持当前有效期」就是这个行为）
- 不在白名单内返回 `400`，且不会调用站点、不会改库

返回更新后的邮箱。站点失败 `502`，错误写入该邮箱的 `last_error`。

### POST /api/mailboxes/:id/refresh
拉取最新邮件并入库。返回：
```json
{"success": true, "data": {"new": 1, "total": 3, "lifetime": "30d"}}
```
站点不可用（邮箱过期/被删）`502`，同时把错误写进该邮箱的 `last_error`。

### GET /api/mailboxes/:id/emails
本地缓存的邮件列表（不含正文全文，带 160 字 `preview`）：
```json
{"success": true, "data": [{
  "id": 3, "remote_id": "abc", "sender": "a@b.com",
  "subject": "验证码", "received_at": "2026-11-06 11:15:00",
  "is_read": false, "preview": "验证码 483920"
}]}
```

### DELETE /api/mailboxes/:id/emails
清空该邮箱的本地邮件。返回 `{"removed": n}`。

## 批量任务

同一时刻只允许一个任务在跑，重复创建返回 `409`。

### POST /api/jobs
```json
{"kind": "fetch", "scope": "all"}
{"kind": "renew", "scope": "ids", "ids": [1, 2, 3]}
```
- `kind`：`fetch`（抓信）| `renew`（续期）
- `scope`：`all` 全部 ｜ 其他值按 `ids`
- `renew` 只会处理 `auto_renew = 1` 的邮箱，没有符合的返回 `400`
- 任务在后台线程按 settings 里的毫秒间隔逐个执行

成功 `201` 返回任务快照：
```json
{"id":"aac614e1754f","kind":"fetch","status":"running","total":1,"done":0,
 "current":"a@b.com","success":0,"failed":0,"results":[]}
```

### GET /api/jobs
历史任务列表（最近 30 条，倒序）。每条是任务快照（含 `results` 明细）。

### GET /api/jobs/active
当前运行中的任务快照，没有则 `data: null`。**前端打开页面时用它恢复进度**；
进程重启后不会再有 running 任务（会被标记为 `interrupted`）。

### GET /api/jobs/:id
任务详情（内存里没有时从数据库读，所以历史任务也能查）。
`status`：`running` / `done` / `cancelled` / `interrupted`。
`results` 形如 `[{"mailbox_id":1,"email":"a@b.com","ok":true,"new":2,"total":9,"at":"..."}]`，
失败项为 `{"ok":false,"error":"收件箱不可用或已过期…"}`。

### POST /api/jobs/:id/cancel
请求终止（当前这一封跑完就停），已结束的任务返回 `400`。

## 配置

### GET /api/settings
```json
{"settings": {
   "fetch": {"gap_mode":"fixed","gap_ms":500,"gap_min_ms":300,"gap_max_ms":1500},
   "renew": {"enabled":true,"mode":"interval","interval_hours":24,
             "daily_time":"03:00","lifetime":"30d",
             "gap_mode":"random","gap_ms":800,"gap_min_ms":500,"gap_max_ms":2000}
 },
 "scheduler": {"enabled":true,"mode":"interval","last_run":"2026-11-06 21:45:19","running_job":null}}
```

### PATCH /api/settings
只传要改的字段即可（深合并），服务端会做范围校验：
- `gap_mode`：`fixed` / `random`
- `gap_ms`、`gap_min_ms`、`gap_max_ms`：0 ~ 60000，min 大于 max 会自动交换
- `renew.mode`：`interval`（每 N 小时）/ `daily`（每天 HH:MM）
- `interval_hours`：1 ~ 720
- `daily_time`：`HH:MM`
- `lifetime`：必须是有效期白名单里的值

保存后立即生效（调度器每轮巡检都会重新读配置），无需重启。

### POST /api/settings/reset
恢复默认（抓信固定 500ms；续期每 24 小时、随机 500~2000ms、30 天）。

## 邮件

### GET /api/emails/:id
邮件全文，并把该邮件标记为已读（返回的 `is_read` 已是 true）。

### POST /api/emails/:id/read
```json
{"read": true}   // false 可标回未读
```

删除单封本地邮件。

## 错误码约定

| 码 | 含义 |
| --- | --- |
| 400 | 参数错误 |
| 404 | 资源不存在 |
| 500 | 未捕获异常（已记日志） |
| 502 | 上游站点调用失败，`error` 里是原始原因 |
