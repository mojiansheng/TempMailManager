## 这是什么

一个本地运行的小工具：一键在 [onetimeemail.com](https://onetimeemail.com) 创建临时邮箱（有效期可选 10 分钟 ~ 30 天，默认 30 天），可勾选 **每日自动续期**，能查看邮件内容，支持**多级分组**和**批量导入已有账户**。

- 后端：Python + Flask（提供本地 HTTP 接口）
- 前端：原生 HTML/CSS/JS 单页，无构建步骤
- 打包：Nuitka（单文件 exe）
- 存储：SQLite（本地 `data/tempmail.db`）

## 三分钟跑起来

```bash
python -m pip install -r requirements.txt
python run.py
# 浏览器自动打开 http://127.0.0.1:8720/
```

打包成 exe：

```bash
python build.py            # 首次会自动装 Nuitka，编译约 3-10 分钟
# 产物：build/TempMailManager.exe（文件属性里的版本取自 build.py 的 APP_VERSION）
```

## 关键事实（别踩坑）

1. **站点创建邮箱必须带 Cookie + CSRF token**，只 POST 会 403。流程见 `交接/站点协议.md`。
2. 创建出来的默认有效期是 **1 小时**，代码会立刻再调一次 `update_lifetime` 改成 30 天。
3. **续期的本质就是把有效期重新设成 30d**，站点会重置空闲计时。所以「每日自动续期」= 每 24 小时调一次续期接口。
4. 读取邮件、续期、删除 **只需要 uuid**，不再需要 Cookie；Cookie 仍然保存，是为了兼容站点可能的策略收紧。
5. uuid 就是邮箱的唯一凭证（等于密码），拥有它就能读写该邮箱。恢复短语同理。
6. 有效期只接受枚举值：`10m 30m 3h 6h 24h 3d 7d 15d 30d`，其它值返回 `Invalid lifetime option.`
7. **导入不需要 Cookie**，但必须能连通站点：邮箱地址要靠 `api_check_emails.php?uuid=` 换回来，顺便验证 uuid 是否有效。
8. 导入解析很宽容：一行里只要出现合法 uuid 就能识别，uuid 在前在后、逗号/制表符/空格分隔都行；表头行（含 uuid/助记词/phrase 等词）自动跳过；`#` 开头为注释。

## 已知限制

- 站点只收不发，不能回信、不能收附件（附件在接口里不返回）。
- 邮件列表接口会返回全部正文，本地做缓存；同一封邮件重复拉取会覆盖更新，不会重复入库（`mailbox_id + remote_id` 唯一）。
- **不再有任何自动抓信轮询**：只在点「抓取邮件」时请求站点，选中邮箱不发请求。
- **所有数据都在 `data/tempmail.db`**：配置（`settings_kv.config`）、调度状态（`settings_kv.scheduler`）、任务与明细（`jobs` / `job_items`）。旧版遗留的 `settings.json`、`schedule_state.json` 会在首次启动时自动导入并改名为 `*.json.migrated`，确认无误后可删。
- 自动续期依赖程序在运行；程序关闭期间不会续期（30 天窗口足够容错），重启后按配置补跑一次。
- 同一时刻只允许一个批量任务，避免两批请求交叉打站点。
- 未做多用户/鉴权，服务只监听 `127.0.0.1`，不要改成 `0.0.0.0` 暴露到公网。
- 导入是**逐行同步请求站点**，几十行会花十几秒；单次上限 300 行，超出的行被忽略。
- 导入只认 xlsx，不支持老式 .xls（另存为 xlsx 即可）；xlsx 用自研读取器，不依赖 openpyxl。
- 分组不支持拖拽排序，顺序按名称排序。

```

└── version/             # 发布投放区（被 gitignore，仅本地保留）
    ├── CHANGELOG.md                      # 每次发版的更新日志（当前仅 v1.0.0）
    └── TempMailManager-v1.0.0-win64.exe  # 当前最新（原 v1.1.1 代码重新发布的首个公开版）
```

**发版流程**：改 `build.py` 的 `APP_VERSION`（同时决定 exe 文件属性里的版本）→ `python build.py` →
把 `build/TempMailManager.exe` 复制成 `version/TempMailManager-v<版本>-win64.exe` →
在 `version/CHANGELOG.md` 顶部追加一节 → 提交源码并打 tag → 在 GitHub 建 Release 上传该 exe。
`github/version/` 与打包产物均不进 git，仓库里只放源码和日志。

发布步骤：在 github/ 内 `git init` → 提交 → 推送到新建的 GitHub 仓库（已配好 origin）。
更新代码后需重新把 `app/`、`run.py`、`build.py`、`requirements.txt`、`start.bat` 同步进 github/。
